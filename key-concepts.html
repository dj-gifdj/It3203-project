Key Concepts

Seven core ideas that tie web servers and web browsers together.

1Client–Server Model

A networking pattern where a client (the browser) requests resources and a server provides them. The client initiates every exchange; the server only responds.

2HTTP / HTTPS

HyperText Transfer Protocol is the set of rules browsers and servers use to communicate. HTTPS adds TLS encryption so the data exchanged can't be read or tampered with in transit.

3DNS (Domain Name System)

The internet's "phone book." DNS translates human-readable domain names like example.com into the numeric IP address a browser needs to reach a server.

4URL (Uniform Resource Locator)

The address of a specific resource on the web, made up of a scheme (http/https), a domain name, an optional port, a path, and optional query parameters.

5Rendering Engine

The browser component that parses HTML and CSS and converts them into the visual layout you see on screen, such as Blink, Gecko, or WebKit.

6HTTP Status Codes

Three-digit codes a server returns to summarize the result of a request — 200 for success, 301 for redirect, 404 for not found, 500 for a server error.

7Caching

Browsers and servers temporarily store copies of resources (images, stylesheets, pages) so repeat visits load faster and put less load on the server.
